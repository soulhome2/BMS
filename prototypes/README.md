# Прототипы

Здесь лежат исполняемые артефакты, а не заметки: их открывают в браузере или запускают,
поэтому папка вынесена из нумерованных разделов документации и названа латиницей.
Подчёркивание — метка «это не документация»: по нему папку удобно целиком добавить в
исключения поиска Obsidian, чтобы служебные README не всплывали вперемешку с заметками.

Каждый прототип — самодостаточная папка `kebab-case`, которую можно скопировать целиком
или отдать коллеге zip-архивом:

```
_prototypes/
  sip-setup/            один прототип = одна папка
    index.html          точка входа, открывается двойным щелчком
    README.md           что это, зачем, какие решения фиксирует, что вне области
    CHANGELOG.md        что менялось и какое решение за этим стоит
    tests/checklist.md  что проверено и работает — список для передачи
    tests/run.js        скрипт, которым получен список (если проверки есть)
    screenshots/        снимки состояний для вставки в заметки
```

## Правила

**Точка входа всегда `index.html`.** Имя файла не повторяет имя папки: путь
`_prototypes/sip-setup/index.html` читается однозначно, а `sip_setup/sip_setup.html`
нет. Так же прототип сразу открывается, если папку когда-нибудь выложат статикой.

**Прототип не заменяет документ.** Он уточняет поведение, но источник истины —
заметки в нумерованных разделах. Каждый прототип связан парной заметкой в подходящем
разделе (для `sip-setup` это `40 - Прототипы SIP/07 - Прототип WEBUI - настройка SIP`),
и заметка содержит ссылку на папку, а README — ссылки на опорные документы.

**Одна страница без сборки.** Прототипы пишутся так, чтобы не требовать `npm run build`,
сервера и бэкенда: иначе через полгода их никто не запустит. Внешние зависимости
допустимы только косметические (шрифты, иконки) и должны быть перечислены в README.

**Данные внутри — демонстрационные.** Никаких реальных адресов, телефонов, паролей и
ключей: прототип уезжает в репозиторий документации и живёт там открыто.

**Правки отражаются в CHANGELOG, чек-лист обновляется при следующем прогоне.** Чек-лист —
самая ценная часть передачи: он говорит, какие решения согласованы намеренно, а не
получились случайно. Поэтому у него всегда стоит дата снимка, и расхождение с прототипом
допустимо ровно до следующего прогона.

**Зависимостей в папке не держим.** Хранилище лежит внутри Яндекс.Диска, и `node_modules`
из нескольких тысяч мелких файлов уезжает в облако целиком. Всё, что нужно для прогона
проверок, ставится во временной папке вне хранилища; скрипт проверок принимает путь к
прототипу аргументом именно для этого.
